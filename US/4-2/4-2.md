# Story 4.2: Visitor to Buyer Conversion

Status: ready-for-dev

## Story

As a visitor,
I want to be redirected to the product I was viewing after registration,
so that I can continue my shopping without friction.

## Acceptance Criteria

1. **Given** a visitor was viewing a product and clicked "Add to cart" **When** they complete registration or login **Then** they are redirected to the product detail page they were viewing

2. **Given** a visitor registers after being prompted by the cart gate **When** registration is complete **Then** their account is created with role "acheteur" and they are logged in

## Tasks / Subtasks

- [ ] Task 1: Frontend — Save redirect URL (AC: #1)
  - [ ] When visitor clicks "Add to cart", save current URL in localStorage or route query param
  - [ ] Pass redirect URL to login/register page as query param (?redirect=/products/123)
- [ ] Task 2: Frontend — Post-auth redirect (AC: #1, #2)
  - [ ] After successful login/register, check for redirect URL
  - [ ] If redirect exists: navigate to that URL
  - [ ] If no redirect: navigate to homepage (default behavior)
  - [ ] Clear saved redirect URL after use
- [ ] Task 3: Frontend — Cart gate UX (AC: #1)
  - [ ] When unauthenticated user clicks "Add to cart", show modal/banner
  - [ ] Options: "Se connecter" (→ /login?redirect=...) or "Creer un compte" (→ /register?redirect=...)
  - [ ] Smooth transition, no jarring redirects
- [ ] Task 4: Tests (AC: #1, #2)
  - [ ] Vitest: test redirect flow after login/register
  - [ ] Vitest: test cart gate modal

## Dev Notes

- FR18: redirection post-inscription vers le produit consulte
- Mecanisme simple: query param ?redirect= sur les pages login/register
- Le role par defaut lors de l'inscription depuis le cart gate est "acheteur"
- UX fluide: le visiteur ne doit pas perdre le fil de son parcours
