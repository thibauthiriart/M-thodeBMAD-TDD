# Story 1.4: Role-Based Access Control

Status: ready-for-dev

## Story

As a system,
I want to restrict features based on user roles,
so that buyers, sellers, and admins only access their authorized features.

## Acceptance Criteria

1. **Given** a user with role "acheteur" **When** they try to access seller dashboard or admin dashboard **Then** they are redirected with an unauthorized message

2. **Given** a user with role "vendeur" **When** they try to access admin dashboard **Then** they are redirected with an unauthorized message

3. **Given** a visitor (not logged in) **When** they try to access protected routes (profile, cart, seller dashboard, admin) **Then** they are redirected to the login page

## Tasks / Subtasks

- [ ] Task 1: Backend — Role middleware (AC: #1, #2, #3)
  - [ ] Create RoleMiddleware to check user role against required role(s)
  - [ ] Register middleware in bootstrap/app.php
  - [ ] Apply middleware to seller routes (role:vendeur)
  - [ ] Apply middleware to admin routes (role:admin)
  - [ ] Return 403 JSON response on unauthorized access
- [ ] Task 2: Backend — Route groups (AC: #1, #2, #3)
  - [ ] Organize routes into groups: public, auth, seller, admin
  - [ ] Apply auth:api middleware to protected routes
  - [ ] Apply role middleware to role-specific routes
- [ ] Task 3: Frontend — Route guards (AC: #1, #2, #3)
  - [ ] Create navigation guard in Vue Router
  - [ ] Check auth state for protected routes → redirect to /login
  - [ ] Check role for role-specific routes → redirect with message
  - [ ] Define route meta: { requiresAuth, requiredRole }
- [ ] Task 4: Tests (AC: #1, #2, #3)
  - [ ] Pest: test middleware blocks unauthorized roles, allows authorized roles
  - [ ] Pest: test unauthenticated access returns 401
  - [ ] Vitest: test navigation guards

- Admin cree manuellement (seeder ou tinker)

- Frontend guards = UX (evite les erreurs 403 visibles)
- NFR11: vendeurs accedent uniquement a leurs produits
- NFR12: acheteurs accedent uniquement a leur panier/commandes
